# Periodic nudge injection during autonomous agent/sub-agent work

Inject nudges periodically (every N turns) only while an agent or sub-agent is working autonomously. This is a SEPARATE counter from the existing user-message counter - they must not interfere.

Two distinct subagent-context toggles:

- `enabled.subagentSystemPromptNudge` (default `true`): injects the nudge into the subagent's initial system prompt via `experimental.chat.system.transform`. Existing behavior.
- `enabled.subagentAutonomousWorkNudge` (default `false`): master switch for the NEW periodic autonomous-nudge behavior. Drives `SubAgentMessageInjector`.

When `enabled.subagentAutonomousWorkNudge=true` and `enabled.subagentSystemPromptNudge=false`, only the periodic path fires.
When `enabled.subagentAutonomousWorkNudge=false` and `enabled.subagentSystemPromptNudge=true`, only the system-prompt path fires (legacy behavior).
When both `true`, both paths fire.

## Acceptance criteria (GivenWhenThen)

- Given `enabled.subagentAutonomousWorkNudge=true` on a prompt, when N turns of autonomous agent/sub-agent work have elapsed since the last nudge for that prompt, then the configured nudges are injected into the next autonomous turn.
- Given a user sends a message via `chat.message`, when the user-message counter is incremented, then the autonomous counter is NOT affected.
- Given an autonomous turn is recorded (via `chat.message` for primary, via `experimental.text.complete` for subagent), when the autonomous counter is incremented, then the user-message counter is NOT affected.
- Given two prompts both have `enabled.subagentAutonomousWorkNudge=true` with different intervals, when turns happen, then each prompt's counter is evaluated independently against its own interval.

## Out of scope
- Subagent-specific scoping (tracked separately as T-002).
- Skipping by message content substrings (tracked separately as T-011).
- Deprecation of `enabled.subagent` -> replaced by `enabled.subagentSystemPromptNudge` (no compat shim).
